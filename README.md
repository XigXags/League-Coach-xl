# League coach prototype

A Windows Discord bot that reads the current League match, proposes plays based on observed facts, asks TypeSafe Jev to rank them, and posts a read with two alternatives in Discord. When joined to voice, it speaks one short line carrying both. Explicit objective comparisons such as “Grubs or Dragon?” now produce two role-assigned routes with a wave setup and conversion step. The supporting macro rules and data limits are in [MACRO_RESEARCH.md](MACRO_RESEARCH.md).

## Coaching update

General calls now cover recent picks and deaths, early lane and jungle tempo, resets, side waves, mid siege, and a wait-for-opening option. Neutral objectives are only one branch of the plan. See [COACHING_MODEL.md](COACHING_MODEL.md) for the decision hierarchy and what the live feed can verify. Older descriptions below of a default objective setup predate this update.

Each lane has a full playbook in [lane_playbook/](lane_playbook): [top](lane_playbook/top.md), [jungle](lane_playbook/jungle.md), [mid](lane_playbook/mid.md), [bot](lane_playbook/bot.md), and [support](lane_playbook/support.md), plus [cross-lane fundamentals](lane_playbook/fundamentals.md). They cover the job, wave and trade mechanics, what each phase asks for, matchups, what the live feed can and cannot show, and common mistakes. The active player's full role playbook goes to Jev with every ranking; the other four get their summaries. Coach also offers one play for your own lane job in the current phase, so a bot-lane player gets trade-window and group options rather than generic map calls. Patch-specific timers stay in [MACRO_RESEARCH.md](MACRO_RESEARCH.md).

Coach now loads the five completed [role research reports](artifacts/role-research/20261005-145811-league-roles-ee9dcf) at startup. Five coordinators sample the live game every five seconds, record observed role changes, and send a compact briefing to Jev when asked. Use `/coordinators` to inspect all five notes, or choose one role. Notes are in memory for the current match and reset when the game clock restarts. They are observations and score clues, not unseen wave, vision, or cooldown facts. A new player question can interrupt speech; ordinary game changes no longer restart an answer mid-sentence.

## Setup

1. Install Python 3.14 on Windows. The Python dependencies include an FFmpeg binary for voice playback.
2. In this folder, run `python -m venv .venv`, then `.venv\Scripts\python -m pip install -r requirements.txt`.
3. Create a Discord application and bot. Invite it to a server with `bot` and `applications.commands` scopes, plus Send Messages, Connect, and Speak permissions.
4. The bot reads `DISCORD_BOT_TOKEN` from the environment, or `DISCORD_BOT_TOKEN.txt` on the OneDrive Desktop. You can point `DISCORD_BOT_TOKEN_FILE` at a different private file. For Jev, it reads your existing OneDrive Desktop file `LaugeCoach_APIkey.txt`; alternatively save only the key in `TYPESAFE_API_KEY.txt` in this folder, or set `TYPESAFE_API_KEY` as an environment variable. Set `DISCORD_GUILD_ID` to your test server ID for immediate slash-command registration. Do not commit or share tokens.
5. Run `.venv\Scripts\python bot.py` on a Windows PC that is playing League.

Your Discord application is **League Coach** (`1556684335543750736`). [Invite it to your server](https://discord.com/oauth2/authorize?client_id=1556684335543750736&permissions=3148800&integration_type=0&scope=bot+applications.commands), then run `.venv\Scripts\python -B verify_discord.py` to check the stored token without printing it.

Commands: `/coach`, `/ask`, `/stop`, `/note`, `/state`, `/coordinators`, `/approach`, `/join`, `/hotkey`, `/miclist`, `/stophotkey`, `/listen`, `/listenstatus`, `/stoplisten`, `/leave`. To talk in text, use `/ask` with a question, or write `@League Coach should we contest dragon?` in a text channel. `/state` shows the facts the bot can read without making a recommendation. Join voice first if you want spoken output. **Recommended on the PC running Coach:** run `/hotkey` once, then hold the **-** key (between 0 and =), ask your question, and release. This captures the local default microphone only while the key is held, stops Coach as soon as the key is pressed, and avoids Discord's unreliable encrypted voice-receive path. You can keep talking to friends with Discord's normal voice activation. If the wrong microphone is used, run `/miclist` and repeat `/hotkey mic:<number>`. `/stophotkey` turns it off. `COACH_HOTKEY_VK` can change the Windows virtual-key code before startup. The older `/listen` wake-word mode remains experimental. `/leave` disconnects entirely. By default, no live game or no Jev means no recommendation. `COACH_MOCK=1` is for offline development only.

Once connected to voice, Coach streams every answer with `edge-tts`, including a short diagnostic when no live match or ranker is available. This gives a recognized wake-word request audible feedback instead of silently leaving one-line status responses in chat.

Factual questions about the fresh local feed bypass Jev. Supported examples include “who's on the minimap?”, the game clock, team rosters, kill/alive score, and the active player's health, level, and unspent gold. Minimap answers name only confident current icon matches; unclear or stale readings are reported as uncertain rather than absent.

An optional OpenAI-compatible intent model can choose one or more of those retrieval tools. Set `COACH_ROUTER_URL` to the full chat-completions endpoint, `COACH_ROUTER_MODEL` to its model name, and either `COACH_ROUTER_API_KEY` or `COACH_ROUTER_API_KEY_FILE`. The router receives the question and a closed tool catalog, not game state. Invalid output falls back to local rules. Only a `decision` route reaches Jev; observation and estimate routes are answered from local tools. Gold difference is explicitly a low-confidence score-derived estimate, not Riot-reported team gold.

## Current limits

- Riot's Live Client Data API is local to the machine running League. Overwolf is a possible later adapter; this prototype uses Riot's documented local API directly.
- Jev ranks options generated from the active player's gold, team alive counts, role matchups, player scores, items, champion archetypes, and recorded objective events. The reasons are concrete play sequences tied to observed facts. It does not calculate total team gold: Riot's local feed supplies unspent gold for the active player only. Practice Tool gold and score may be artificial and are downweighted. Validate usefulness during real matches before trusting calls.
- General “what now?” questions include lane control, side-tower pressure, and one timely objective setup rather than defaulting to a Grubs-versus-Dragon pair. The sourced Worlds sample, data-coverage limits, and next research steps are in [WORLDS_RESEARCH.md](WORLDS_RESEARCH.md). Chat posts the read with two alternatives and their full reasoning; the spoken call is one short line carrying both ("... Or, ..."), with no numbered plans.
- Junglers get long-horizon options: the coach places you on a level 6 timeline (first clear, second clear, six race, behind or first to 6, after 6) from observed levels and game time, and words anything it cannot see (camps, crab, stacks, cooldowns) as a check for you. Your own benchmarks and farm-first or gank-first champion lists live in [lane_playbook/lessons.md](lane_playbook/lessons.md); edits load on the next answer without a restart, and problems in the file are printed in the bot log as `Lesson file: ...` at startup and on the first answer after each edit. A jungler always hears the clear or scaling plan as one of the two alternatives.
- Plans for this match: the coach remembers the plan you pick and the last pair it offered, on the coordinator board, until the match ends. Pick one by saying so ("let's play for six on crab", "going with the invade", or "first one" / "the other one" / the name of a plan just offered, within two minutes of an offer). A plan is picked only by a statement with the plan named right after the verb: a question ("should I take the crab?", "ok so do I gank") never picks one, and the spoken answer opens with "..., locked" when one was. "What are my options?" lists up to four; "what else" skips what you just heard. "Am I on track?" (or any broad question such as `/coach`) compares your level, CS, deaths and the clock with the plan's marks and says on pace, behind the mark, slipping (with the observed cause: a death, their jungler ahead, or a score edge down), off, done, or that the plan's window has passed; it never claims camp, crab or stack progress. A plan that goes off is said once with the safe lines and then set aside, so later questions get the ordinary options. "This isn't working" or "a safer way back" sets the plan aside and offers two safe lines; a question such as "is it safer to gank top?" only adds the safe lines; "drop the plan" forgets it. Every answer still carries two alternatives and the choice stays yours. Further jungle options appear only under an observed trigger: reset on your own side or trade sides when you are behind or dead, one enemy camp while their jungler is dead, playing through a lane that is ahead on score, and tracking for a counter-gank. Laners get a hold-at-tower line when behind.
- In `lessons.md`, `Offer at:` (instead of `Trigger:`) turns a lesson into a plan of its own, with `Kind`, `Name`, `Pick it with` and `On track` marks such as `level 4 by 3:30`. The marks shipped for "six on crab" and "blue into an invade" were set by the coach from your benchmark, not from confirmed XP maths; edit them freely.
- `lane_playbook/pro_lessons.md` is optional. It holds tendencies from professional games written in our own words (no quotations), validated in the log as `Pro lesson file: ...`. Up to three that match your role, game phase and observed situation go to Jev as background; they are never offered as an option and never appear in a first answer. Only the third "explain more" layer names one, as background and not as a read of your game. An optional `Archetypes:` line (Fighter, Tank, Mage, Assassin, Marksman, Support) says which kinds of champion a lesson is about; no shipped lesson has one yet. The source transcripts are in `transcripts/` and already downloaded, so no Kaggle token is needed to run the coach.
- **Stop.** Saying "stop" (also "quiet", "shut up", "enough", "never mind", "cancel" and similar, as the whole sentence, repeated or with filler: "stop it, stop it", "stop, coach", "stop. thank you") ends the current speech and discards an answer still being computed: nothing is posted, spoken or echoed, and the plan, the last offer and the remembered read are untouched. It works on the push-to-talk key, as "Coach, stop" on `/listen` (a bare "stop" also works there while the coach is speaking; `LISTEN_BARE_STOP` in `bot.py` turns that off), as `/stop`, `/ask stop` or a mention. "How do I stop the dive" is still a question. Each one is logged as `Stop heard: ...` so the word lists in `coach.py` (`STOP_PHRASES`, `MORE_PHRASES`, `NOISE_PHRASES`) can be tuned; how Whisper `tiny.en` writes a bare "stop" or "more" has not been measured.
- **Explain more.** "Explain more", "keep going", "why", "go on" (or "why the second one", "why gank") elaborates on the two alternatives of the last delivered read without reading the game or asking Jev again: first why these two, then what to check and what breaks them, then background (the lessons of yours that stand behind either alternative, your note, and a pro tendency only when it shares an observed situation with the read, spoken together with what the feed showed), then "that's everything". "More on that", "why these two", "explain the gank plan" work too. Every layer names both alternatives and ends "Your call."; chat says "as of M:SS" and the two layers that repeat what the feed showed always open with "From the M:SS read". A lesson's "Feed check" line is quoted as the lesson's own condition, not as a fact about the match. The spoken part is at most 80 words of whole sentences; longer sentences stay in chat, and a lesson's benchmark is never spoken without its "By your own benchmark" opening. The read is forgotten after 3 minutes idle, 6 minutes in total, or a new match, and then "more" gives a fresh read. `EXPLAIN_PRO = False` in `coach.py` keeps pro tendencies out.
- **Delivered-only memory.** The bot now writes the plan, the offer and your notes only when an answer is actually posted. An answer that a newer question or a stop replaced changes nothing, so "I'll farm" followed by a key press before the answer arrives is not committed; say it again.
- **Champion kits.** `champion_kits.json` holds Riot's own ability names and short descriptions for all 173 champions (Data Dragon 16.19.1, no cooldowns, ranges or costs). Rebuild it per patch with `.venv\Scripts\python -B build_champion_kits.py`. Jev gets your kit, your role opponent's and, for laners, the enemy jungler's as background on what a champion can do; kit text is never spoken or shown, and never says what is ready or happening.
- **Your notes on a champion.** Once a match, in the first 15 minutes, if nothing on file says how you play your champion (no lesson naming it, no note, no `Archetypes:` line in a pro lesson), the answer opens with "No notes on X yet, tell me how you play it" and still gives two alternatives. Answer in one sentence within three minutes ("I play Zac for ganks from level four"), or say "note that ..." at any time, or use `/note`; `/note` with no text lists them. A spoken note has to be in the first person or name the champion ("note that I gank early"), so "remember their jungler is bot" is not stored, and a bare plan pick ("full clear") only picks the plan. The exact stored text is shown in chat; if the file cannot be written or read, the answer still comes and a second line says the note was not saved. Notes are your own words, appended to [lane_playbook/champion_notes.md](lane_playbook/champion_notes.md) (edit or delete freely), sent to Jev as `player_note`, shown by `/coordinators`, and read back only as "Your own note on X".
- Voice uses `en-US-SteffanNeural` at `-6Hz` pitch, `+30%` rate, and `+5%` volume. Audio streams into playback as soon as the first chunk arrives, instead of waiting for the whole answer to synthesize. If the neural voice returns nothing, Coach falls back to local Windows speech. The spoken answer is sent to Microsoft's Edge speech service for synthesis. Set `COACH_VOICE`, `COACH_VOICE_PITCH`, `COACH_VOICE_RATE`, or `COACH_VOICE_VOLUME` to adjust it. Samples of other voices are in `voice_samples/`. A bundled FFmpeg binary handles playback. Each answer logs `Answer ready in X s`, `First audio in X.X s` and `Spoken call finished in Y s` in `bot.out.log`. Discord voice requires DAVE support; `discord.py[voice]>=2.7.1` is specified.
- Incoming voice uses a pinned DAVE-compatible fork of `discord-ext-voice-recv` and local `faster-whisper` with the small English model. The first `/listen` may download the model and take longer. Whisper turns speech into text; it is separate from the bot's speech synthesis. This voice receive extension is experimental, so verify in a real Discord call before depending on it during a match.
- `/hotkey` uses local `sounddevice` microphone capture and Windows key polling (the - key by default) on the PC running the bot; it does not require Discord to decrypt incoming speech. It discards microphone samples outside the held key and does not save audio. Only the player on that PC can use this key; teammates on other PCs can use text commands. If a game or input mode blocks global key detection, `/listenstatus` shows whether a hotkey question completed.
- A fresh recognized "Coach..." question interrupts current playback and supersedes an answer still being computed. During spoken calls, the bot rechecks the local game about once a second; deaths, level or item changes, objective events, or the active player's health crossing below 30% stop the old call and trigger an updated one. It limits automatic updates to prevent a fight from making it talk nonstop. This is not continuous frame-level map vision.
- No API keys are needed for the local unit tests: `python -m unittest -v`.

## Policy

The coach always presents two alternatives, in chat and in speech, and the player decides. Riot's general policy allows highlighting important decisions and presenting multiple choices, while its League policy lists apps that dictate player decisions as unapproved. Register the product and seek Riot feedback before any public release. See https://developer.riotgames.com/policies/general and https://developer.riotgames.com/docs/lol.
